# 角色资料模板 v1（Part 24j）

一个角色一个 `.md` 文件。管理员在 **角色工作台 → 导入角色资料** 里一次选多个文件：先看预览（什么都不写），确认后才导入。
导入只进入**草稿**：不发布、不改目录位置、不碰声音批准、素材、玩家和聊天。示例：`examples/character-template.example.md`（虚构）。

## 规则

- **字段名一字不改**（全角／半角冒号都行，半角括号会按全角读；`生日` 后面可以跟 `（YYYY-MM-DD）`）。
  未知、缺少、改名的字段不会被猜，而是报出位置（文件 · 分区 · 字段 · 第几项）。**任何一个错误会阻止整次导入。**
- **空值 = 没有材料**：新角色保持为空；已有角色**保留现值，不会被清空**。
- 一个字段占一行：`- 字段名：值`。值太长可以换行（缩进的行属于上一个字段），列表也可以写成缩进的子项。
- **列表字段**（自称、别名、中性称呼、黑称、常用词与口头禅、不会使用的措辞）：每项写在 `「…」` 里，或用 `、` 隔开。项目内部的空格原样保留。`「」` 之外多出的文字是错误。
- **同一个名字**可以同时是黑称和另一类（别名或中性称呼），各算一个别名（类型不同）；其余的重复（自称与别的类、别名与中性称呼……）仍是错误。他人名片里，对他是黑称的名字**只**出现在“不要主动这样叫”里。
- 分区标题 `## N 标题` 与字段 `- 字段：值` 的顺序如下表；字段的先后不强制，但每个字段都必须出现（可以留空）。
- 长度都按 JavaScript 字符串长度（一个汉字 = 1）。超出上限是**带位置的错误**，不会被截断，也不会挪到别处。

## 字段与去向

| 分区 · 字段 | 格式 / 上限 | 去向 |
|---|---|---|
| 1 · 角色代码 | 2–12 位 `A-Za-z0-9_-`，大小写不分唯一 | 角色代码表；身份与展示可改 |
| 1 · 人设名称 | ≤12 | `name`；关系与故事的主名 |
| 1 · 网页展示名／昵称 | ≤100 | `displayName` |
| 1 · 自称 | 列表，每项 ≤25 | 别名（kind `self`，态度 喜欢） |
| 1 · 别名（含英文名） | 列表，每项 ≤25 | 别名（`other`，喜欢） |
| 1 · 中性称呼 | 列表，每项 ≤25 | 别名（`neutral`，可以） |
| 1 · 黑称 | 列表，每项 ≤25 | 别名（`insult`，不喜欢） |
| 1 · 饰演过的角色、动物形象、性别设定、身高 | 文本（身高 ≤40） | 其余设定 `profileFacts` |
| 1 · 生日 | `YYYY-MM-DD`，真实日期 | `birthDate` |
| 1 · 头像／形象图片文件 | 只写文件名 | 记在角色代码下；清单「头像 X 待 25e 上传」 |
| 1 · 一句话描述 | ≤500 | `publicDescription`（公开简介）。只写这里；不再写名片 |
| 1 · 名片一句话（**可选**，紧跟一句话描述；没有这一行的旧文件照常导入） | 单行，≤40 | 名片的一句话（`identity.oneLiner`）。没写时：一句话描述 ≤40 字就用它；超过 40 字则名片的一句话保持不动，并进清单「名片一句话待填（一句话描述超过 40 字）」（提醒，不是错误） |
| 1 · 音色模型 ID（Fish Audio） | ≤128，`A-Za-z0-9_-` | 声音页「已有 Fish 音色 referenceId」预填；不生成、不批准、不调用 Fish |
| 2 · 欢迎词 | `「…」` 行，每条 ≤500，最多 12 条 | 第 1 条 → 欢迎词；第 2 条起进清单「欢迎词 第 N 条 等 24k 多欢迎词」 |
| 2 · 角色主色 | `「#2F4858 深墨蓝（主）」「#C9A227 旧金」` | `presentation.palette`（有序，含 role）；（主）的色值 → `color` |
| 2 · 是否为成长中角色 | 是／否 | 是 → `seed: true`；否 → 去掉 |
| 3 · 五项相处方式 | 文本，合计 ≤20,000 | `persona`：每项一行「字段名：内容」，按模板顺序 |
| 4 · 八项语言特征 | 文本；两个列表项各 ≤100 字 | `authorCanon.speechStyle`：每项一条「字段名：内容」 |
| 5 · 成长背景、现在的生活状态；6 · 近况 | 文本 ≤2,000 | `authorCanon.background`：`{title: 字段名, text}` |
| 5 · 兴趣·擅长的事、喜欢与不喜欢的事物、宠物、家庭成员、外貌·衣着·体态、学校-年级；6 · 现在所在地 | 文本 ≤2,000 | `authorCanon.profileFacts` |
| 8 · 四项边界 | 文本 ≤2,000 | `authorCanon.boundaries` |
| 7 · 关系块 | 见下 | 关系与故事（合并，从不替换） |

**新角色必填**：人设名称、网页展示名／昵称、欢迎词（至少一条）、第 3 分区至少一项（工作台不接受空的人设）。

### 色值与（主）
- 带 `#RRGGBB` 的才会存；没有色值的颜色**不存**，进清单「颜色 X 没有色值，请在工作台选色」。
- 只有一种颜色且没标（主）时，它就是主色。有多种颜色时必须恰有一个（主）；两个或一个都没有 → 错误。

### 7 人物关系
每个 `### 关系 N` 是一个块，**N 没有意义**，块由「对方角色代码」识别（同一对方只能出现一次，也不能是自己）。字段：
`对方角色代码`、`CP名`（≤24）、`本角色如何称呼对方`（`「」` 项，≤6 项每项 ≤16；**没有 `「」` 的文字是一项，原样，绝不按 `/`、`、`、空格拆开**）、`本角色对对方的态度`（≤100）、`相处方式及共同经历`（每一侧 ≤600）。

写入（A 的文件里的一个块 A→B，B 的代码能对上本次导入的角色或关系与故事里已有的角色）：

- 称呼与相处：方向 A→B 的 `addresses` = 称呼项，`treatment` = 态度。
- 故事：每对一个，标题「A与B」（按代码字母序，A 在前），参与者 [A, B]，概述 = 先写的一方的文字，详情 = 每方文字前加 `（人设名称侧）`；已有的同名同参与者的故事只更新各自这一侧。
- 梗：CP名 → 一条，key = CP名，当事人 [A, B]，含义 = CP名。两边 CP名不同 → 该对的错误。
- B 对不上任何角色：警告，什么也不写。评分永远不写；关系与故事里其余内容不动。

### 旧文件
- `自称与其他别名` 仍可读：每项都成为别名（`other`），并进清单「自称与别名未分开，请手动把自称移出」。
- 分区 6 里没有标签的条目读作「近况」。
- 其余未知、缺少、改名的字段仍是带位置的错误。

## 角色代码怎么对上角色
1. 代码表里已有这个代码 → 就是它。
2. 否则，**还没有代码**、且人设名称相同的已有角色 → 预览里标「将绑定代码 X」（先前阵容文件导入的草稿就这样拿到代码）。
3. 否则 → 新建草稿角色。
同一次导入里两个文件同一个代码，或一个代码对上两个角色 → 带位置的错误，什么也不写。
